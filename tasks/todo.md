# 状態の MECE 化と全ステータスの期待値テスト（2026-09-23 着手）

依頼: 「claude, codex, jev で、このシステムの変数を MECE し、すべてのステータスとして理想的な動きをテストケースにして、全部期待値どおりに動くよう自律改善」

## 役割
- Claude(調査サブエージェント) と Codex(`codex exec -s read-only`) が**独立に**変数・値域・出力を洗い出す
- 食い違い・「理想の動き」が割れた所だけ Jev に A/B で判定させる（Jev は生成できない。比べるだけ。対照問題を必ず混ぜる）
- 適用(コード変更)はメインが 1 ステップずつ。サブエージェントは調査と案まで

## 手順
- [x] 1. 変数の洗い出し（Claude / Codex 独立）→ 突き合わせて `docs/state-spec.md`（入力変数・値域・出力チャネル・理想の動き）
- [x] 2. 割れた所を Jev で判定（並びを入れ替えて 2 回以上・対照つき）
- [x] 3. 期待値の「正解の出し方」を decide.py と**別に**仕様から書く（`scripts/uat/state_oracle.py`）
- [x] 4. 全組み合わせを生成して decide() と照合（純関数・数千件）
- [x] 5. 画面側（カードの色・状態名・印・一言、音・小窓・Dock）も同じ期待値と照合（偽 snapshot）
- [ ] 6. 落ちたものを直す → 全件回す、を繰り返す
- [ ] 7. UAT 全件・変異テスト（直した所を戻すと落ちるか）・Codex に反証させる
- [ ] 8. コミット（push は確認してから）

## 既知の候補（着手時点）
- カードの色/状態名(overview.html の stKey)が decide.py と別に決まっている
- 表に無い変数: 自動続行の設定・解除時刻の有無・予約の有無・アカウント数・通知の許可・Claude/Codex・無人実行・遠隔(macmini)

## 経過（2026-09-23）
- Claude 調査役・Codex が独立に「表の答えが印と自動処理にしか使われていない」と結論。理想と違う所 Claude 18 件・Codex 29 件
- Jev: 判断の割れた 12 問を 2 回ずつ（対照 0.97/0.98）。結果は docs/state-spec.md の根拠欄
- 実装: decide.py を 19 行・全チャネルの列に。ui は上書きの後で 1 回。盤(cardKey/cardLabel)・アプリ(音・小窓・Dock・通知・タブの印)・集計・TUI・スマホが ui を読む
- 試験: SM-01(64,512 通り)・SM-02(監査の 18 件を観測から再現)・SM-03(画面)。DT-01/AT-01/LP-04/BD-02/SN-01/AP-14/AU-03 を新仕様に
- Codex の反証で私の「全部 ui を読む」は不成立と判明 → 11 件を追加で修正（Codex の上限がエラーに化ける退行を含む）
- SM-03 が実バグを 2 つ捕まえた: 定数の宣言位置で盤が描けない(TDZ)・ループ待機で wake が無いと盤全体が止まる

## 残す（この回では扱わない。Codex/Claude の指摘）

- 他のジョブ(npm run dev 等)が AI のカードとして出る
