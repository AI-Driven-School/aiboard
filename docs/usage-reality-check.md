## 合っていなかったこと → 直したこと

1. **束ね方が実態に合っていない（最大の不一致）**
   盤は「顧客 → プロジェクト（cwd のフォルダ名）」で束ねる作りだが、**人の会話の 82% は `~` で動いている**ので、ほぼ全部が 1 つの「自社・その他」枠に入り、しかも直近 20 件で打ち切られていた。顧客が付くのは 21% だけ。
   → **触っているファイルの置き場で持ち場を決める**ようにした（`overview.work_root` / `project_hint`、索引側は `_hint_from_files`）。いま動いている 10 件のうち **8 件**に持ち場が付き（自社の作業フォルダ 5 種に分かれた）、過去 30 日でも **97 件**が名前付きの枠に分かれる。`~/Desktop/ECX` のように 1 段では足りない所は 2 段見る。道具置き場（`.claude` など）と、直下に置いただけのファイルは持ち場にしない。試験: WR-01 / WR-02 / WR-03。

2. **長い依頼を送ると行が混ざる**
   3,500 字を送ると、貼り付けが終わる前に Enter が飛んで行が途中で切れていた。依頼の中央値は 9 回・p90 53 回で、長文を貼る使い方は日常。
   → 端末ごとに **1 件ずつ順番に**送り、Enter は貼り付けの長さに応じて待つ（最大 0.8 秒）。試験: AP-09。

3. **入れ子の AI を本体と取り違える**
   1 セッションが道具を最大 4,996 回使い、24.9% が子を持つ。子として `claude -p` を起こすと、pid が一周した後では**内側の一時実行をセッション本体と誤認**していた（メモリ・状態・「終了」の宛先が全部ずれる）。
   → 他の AI の子孫でない「外側」を選ぶ（`cs.outermost_ai`）。試験: CS-05。

4. **`~/logs/codex` のようなファイルを Codex セッションと誤判定**
   → コマンド行の先頭（node 経由なら 2 つ目）だけを見る。試験: CS-04。

5. **壊れた 1 行で索引が全部落ちる／題名に API キーが残る**
   会話ログは 13,430 本もあり、1 本でも壊れれば 30 日分の索引が作れなくなっていた。
   → `prompt_text` を壊れた行に強くし、題名も伏せ字の対象にした。試験: IX-08 / IX-09。

## 直したこと（続き・2026-09-18 夕）

6. **新しいフォルダで開いた claude が、最初の確認で止まったまま何も言えなかった**
   claude は未知のフォルダで「このフォルダを信頼しますか」を出す。iTerm のタブなら画面文字で気づけたが、
   **アプリ自身の端末は AppleScript で画面を読めない**ので、盤は「起動中?」と出すだけだった。
   → 各アカウントの設定にある答え（`hasTrustDialogAccepted`）を見て「確認画面で停止」と出し、
   会話ビューから「はい、信頼する」（↓+Enter）／「いいえ（終了）」で答えられるようにした。試験: TU-01 / TU-02 / CS-06。

7. **通知が macOS に届いていなかった**
   この Mac の通知設定で AIBoard は **denied** だった。Dock の数字は出るので気づけず、
   「あなたを待っている」を知らせる通知は 1 通も出ていなかった。
   → 許可の状態を盤の上のバーに出し（押すと設定画面へ）、実際に 1 通出して配信を確かめる試験を入れた。試験: NT-02 / NT-03。

8. **Claude Code の中から AIBoard を起動すると、アプリの端末で開いた claude が全部見えなくなっていた**（2026-09-19）
   親の Claude Code が付ける環境変数（`CLAUDECODE`・`CLAUDE_CODE_CHILD_SESSION` ほか）が端末に受け継がれ、
   子の claude は「Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker」で記録を書かない。
   盤は記録から状態を作るので、そのセッションは「起動中?」のまま。本物の AI に送る試験（RE-01）を通そうとして発見。
   → 端末を始める時にその印を消す（アカウントの指定 `CLAUDE_CONFIG_DIR` は残す）。試験: AP-17。
   あわせて、claude が初回の確認画面（Chrome 連携など）で止まっている時、会話ビューから Esc / Enter で先に進めるようにした。

## まだ耐えていないこと（判断が要る）

- 無人実行を表示に入れると重い → **畳んだ**（2026-09-18）。無人実行は「持ち場 × 日」で 1 枚に畳む。
  **訂正（2026-09-19）**: 当初「1 フレーム 35ms → 8.3ms」と書いたが、**日時・負荷の違う 2 回を比べており、しかも 8.3ms は 120Hz 画面の上限値**だった（codex の反証で判明）。
  同じ回・同じ条件（load 87→66）で測り直した値: 畳まない **1,813 枚**でスクロール中の p50 8.8ms / **p90 16.9ms**、畳んで **162 枚**で p50 8.3ms / **p90 9.1ms**、最大の束（1,335 件）を開いて 1,497 枚でも p90 9.3ms。
  効いているのは枚数（1,813 → 162）と、重い瞬間（p90）の半減。中央値では差が見えない。測り方は `?nofold=1` と比べる（計測用）。
  **再反証を受けて交互に測り直し（2026-09-19 14:40, ABBA×2, load 18→28）**: 畳んだ状態は 4/4 回 p90 9.0〜9.3ms、畳まないと 2/4 回で 16.7〜17.1ms。
  ただし**最大の束（1,400〜1,500 枚）を開くと p90 9.2〜24.4ms で、畳まない時と同等以上に悪化**していた（1 回目の反証の疑いどおり）。
  → 開いた束から一度に出すのは新しい順に 200 件まで、残りは「さらに N 件」。上限後は開いた状態も 4/4 回 p90 9.0〜9.3ms（load 35〜42）。束を押すとその日の中身が開き、検索は畳んだ中まで届く。試験 BD-17。
- **332 時間続くセッション**: 「終了」の判定と `ago` 表示はできているが、長時間開きっぱなしの会話ログは 171MB まで育つ。いまは末尾読みで 0.01 秒だが、索引の再構築では毎回全部読む。
- **顧客の色分けが 21% にしか付かない**: いまはフォルダと語句で判定している。持ち場（項目 1）が付いたので、**持ち場 → 顧客**の対応表を持てば増やせる。
