# メモリの内訳（2026-09-18 実測）

測り方: `python3 scripts/measure-memory.py 20`。計測用に `.app` を 1 つ起動し、20 秒後に測って自分で終了する（動かしているアプリには触れない）。データ置き場は一時フォルダ、索引は読み取りのみ。

**RSS ではなく footprint（実メモリ）で判断する。** RSS は圧縮されたメモリを隠すので、盤の画面のように圧縮が効くプロセスでは小さく見える（この計測でも WebContent は RSS 100MB・footprint 140MB）。

| 内訳 | RSS | footprint | 何がここに乗るか |
|---|---:|---:|---|
| アプリ本体（Swift・端末 1 枚） | 111MB | **59MB** | libghostty の面・AppKit・端末の履歴 |
| WebKit WebContent（盤の画面） | 100MB | **140MB** | 盤の DOM とカード・索引から引いた 30 日分の記録 |
| WebKit GPU | 50MB | **56MB** | 盤の描画 |
| WebKit Networking | 18MB | **8MB** | 127.0.0.1 への取得のみ |
| 盤サーバ（Python） | 108MB | **50MB** | snapshot・会話ログの読み取り・SQLite |
| **合計** | 387MB | **313MB** | |

## 読み取れること

- いちばん重いのは**盤の画面（WebContent 140MB）**で、アプリ本体（59MB）ではない。減らすなら、盤に出す件数（過去 30 日のカード）と、そのために持つ配列が的になる。
- 盤サーバは 50MB。索引作りを子プロセスに出して結果だけ受け取る形にした後の値で、以前 319MB まで育っていた頃とは別物（[feedback_rss_hides_compressed_memory] の是正後）。
- 「いま」だけを表示している状態の計測。「過去」を開くと WebContent は増える（30 日分の記録を持つため）。

## この数字の位置づけ

- 端末 1 枚・盤を開いた直後の値。端末を増やすと、アプリ本体が 1 枚あたり十数 MB 増える。
- 1 回の計測であり、繰り返し測って分布を見たわけではない。再現手順はスクリプトに残してあるので、変更の前後で同じ条件で測って比べること。
