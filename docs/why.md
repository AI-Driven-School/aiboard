# AIBoard が解く課題（2026-09-20・実測に基づく）

## 1. 課題：エージェントが増えると、人は「自分の番」を見失う

1 本なら端末を見ていればいい。増えると、止まったことに気づけない。この Mac で数えた実物:

| 何を数えたか | 実測 | 出どころ |
|---|---|---|
| いま動いているセッション | **19 本**。うち **11 本が人の返事待ち**（返答待ち 8・判断待ち 3） | 2026-09-20 の snapshot |
| 同じ持ち場で並行している | 1 フォルダに **14 本**、別に 2 本 | 同上 |
| 顧客が自動で付いたセッション | 19 本中 **3 本**（残りは「どの案件か」が画面から分からない） | 同上 |
| 30 日で AI が止まった**出来事** | **1,585 件**（認証 989・上限 495・一時的 90・クレジット 11）。1,255 本の会話が止まった | 会話ログ 6,954 本を 1 行ずつ。**連続する同じエラーは 1 件にまとめた**（2026-09-20 再測） |
| 止まってから人が戻るまで | 中央値 **7.5 分**・p90 **3.3 時間**・1 時間超が 87 件 | 同上（止まった直後から、その会話に人が次に書くまで） |
| 止まったまま、その会話に人が戻らなかった | 認証 989 件のうち **925 件**（94%）／上限は 495 件中 242 件 | 同上。ただし「気づかず放置」と「そこで用が済んだ」を区別できていない（上限値） |
| 会話が圧縮された回数 | 124 | [continuity-ux.md](continuity-ux.md) |
| OS 通知 | この Mac は通知が **denied** で、1 通も出ていなかった | 2026-09-18 実測 |

痛みは 4 つに分かれる。

1. **止まったことに気づけない。** 認証で止まった 989 件のうち、人がその会話に戻ったのは 63 件だけ。
   止まった AI は静かで、端末を見に行くまで分からない。通知は利用者が切れる（実際に切れていた）。
2. **どれが自分の番か分からない。** 19 本のカードのうち 11 本。「作業中」と「返事待ち」は、端末を開いて読むまで区別がつかない。
3. **止まった後、どこから再開すればいいか分からない。** 戻るまで p90 で 3.3 時間空く。「続きから」と言っても、AI は自分が何をしていたか忘れている
   （圧縮 124 回）。人も、どの操作が途中で終わったか覚えていない。
4. **端末が散らばる。** 顧客・案件をまたいで並行すると、どのタブが何だったか分からなくなる。
   同じフォルダで 14 本動いていれば、衝突にも気づけない。

## 位置づけ：端末はそのまま、気づくための盤（2026-09-21 決定）

「iTerm の代わり」を目指して作ったが、実測はそう使われていないことを示した。

| 測ったもの | 実測 |
|---|---|
| 作った本人の Mac で動いている AI セッション | 15 本すべて iTerm。AIBoard の埋め込み端末は **0 本** |
| 直近 24 時間に人が打った依頼 | 181 件のうち盤から送ったのは **4 件（2.2%）** |
| 盤（会話ビュー） | 常時開かれている |
| 独立した判定（Jev・選択肢の順番を入れ替えて 3 回） | 「端末ごと乗り換える」より「**iTerm のまま盤として併用**」が事実に合う（0.99〜1.00）。対照の問いは両順で正解 |

なので**売りを「端末の置き換え」から「気づくための盤」に変えた**。埋め込み端末は残すが、使いたい人のための選択肢として扱う。
置き換えを狙うなら先に要るのは盤の機能ではなく端末の基本（⌘F 検索・利用者が割る分割）で、Jev もそれを
「乗り換えない一番の理由」に挙げた（0.52〜0.60。ただし事実の中で機能の欠けだけを具体的に書いたので、引っ張られた可能性がある）。

## 2. どう解くか：拾う → 決める → 見せる → 触る

AIBoard は**エージェントを動かす道具ではない**。既に動いているものを**拾って、状態を決めて、一手を出す**道具。

### 拾う（状態の出どころを公開する）

| AI | 何を読むか |
|---|---|
| Claude Code | hook が書く状態（`board/hooks/tab-status.py`）＋会話記録の末尾（認証・上限・圧縮・中断） |
| Codex | 自身の状態 DB と rollout の切れ目（task_started / task_complete / error） |
| サブエージェント | `claude agents --json` |
| Gemini / Grok / Cursor | 状態の記録を持たないので、端末が文字を出しているかだけ（5 秒以内＝作業中・30 秒無音＝人の番かも。断定しない） |
| 別の機械 | `ssh` で相手の記録を読むだけ（送らない・止めない） |

### 決める（判断を 1 つの表に集める）

散らばった if ではなく、**14 行の優先順位つき決定表**（[board/decide.py](../board/decide.py)）。
上から見て最初に当たった 1 行が、状態・印・音・小窓・**次の一手**を決める。文書
（[state-truth-table.md](state-truth-table.md)）はこの表から生成し、試験 DT-01 が全行を突き合わせる。
並び順の根拠は上の実測: **人が直さないと永久に進まないもの**（認証 989 件・戻り率 6%）を上に、
時間や AI 自身が解くもの（一時的な失敗 90 件・戻り率 93%）を下に置く。

### 見せる（1 枚の盤・一手だけ）

顧客と案件で束ねたカード。赤＝判断待ち、黄＝あなたの番、紫＝上限（解除時刻つき）、緑＝作業中。
Dock の数字と、通知が切られていても届く**最前面の小窓**と音。同じ場所で並行していれば `⇉N` を出す（畳まない）。

### 触る（同じ会話のまま続ける）

左が会話（LINE 風）、右が**本物の端末**（libghostty なので TUI がそのまま動く）。常に同じセッションを指す。
止まり方ごとに一手は 1 つ: ログインし直す／鍵の棚／請求ページ／別アカウントに移す／解除時刻に自動で続ける。
中断された会話には「**この続きから**」を出す（最後の依頼・済んだこと・**結果が返っていない操作**・止まり方を
記録から拾い、再開のときに AI へ渡す）。

## 3. 他のプロダクトとどう違うか

比較の元は [R6_competitors_2026-09-18.md](R6_competitors_2026-09-18.md)（17 製品＋AGI Cockpit を公開情報で比較）。
似た痛みに、入口が違う。

| | 多くの製品（cmux / Conductor / Vibe Kanban / AGI Cockpit など） | AIBoard |
|---|---|---|
| **対象** | **その道具の中で起こしたタスク**（worktree やタスク欄から開始） | **既に動いているセッション**を tty で拾う。普段の iTerm・tmux・別の機械のものも |
| **主役** | タスク（作る・並列に回す・完了させる） | **止まり方と、次の一手**（作るのは主役ではない） |
| **状態の取り方** | 非公開のことが多い（Cockpit は記載なし） | 公開。hook・rollout・`agents --json`・端末の出力。**どこから来た情報か**を画面にも書く |
| **束ね方** | リポジトリ / worktree 単位 | **顧客・案件**単位（受託で並行する人向け）。持ち場が同じものは畳まず並べる |
| **端末** | Web の疑似端末や差分ビューが多い | **本物の端末**（libghostty）。Claude の TUI・vim・tmux がそのまま動く |
| **判断のロジック** | 製品の中に隠れている | **14 行の表 1 つ**に集め、文書を生成し、試験で固定（DT-01） |
| **外へ出るもの** | クラウド同期・アカウントを前提にするものがある | 既定で **1 つも外へ出さない**。測る道具つき（`scripts/prove-local-only.sh`：2026-09-18 の 90 秒で他所への接続 0） |
| **値段** | 無料＋有料（Cockpit は Autorun と遠隔だけ月 $20 など） | MIT・全部無料 |

**正直に、勝っていない所**:

- **Autorun / Master Agent のような「仕事を分解して 5 本並列に回す」まとめ役は無い。** できるのは
  「任せる」（上限でない AI を 1 本起こす）と、予約（1 回だけ・解除時刻）まで。
- **遠隔は同じ Wi-Fi か自分の VPN 経由だけ**（`/m`）。中継サーバを置かない方針なので、Cockpit のような
  どこからでも使える PWA にはならない。
- **埋め込み端末つきのアプリは macOS のみ。** Linux は盤だけ（tmux 経由で状態を見て、キーを送る）。Windows は無い。
- **状態が分かるのは Claude と Codex だけ。** 他の CLI は「出力が続いているか」しか見ていない（断定しない表示にしてある）。
- **判定器を賢いモデルに替える利点が、まだ見つかっていない。** 手元の 3 モデルで測ると、規則と違う答えが増えて
  遅れが 1〜2.5 秒つくだけで、その違いが良い方向だという証拠が出なかった（[judge-measured.md](judge-measured.md)）。既定は規則のまま。

## 4. 向く人・向かない人

**向く**: 複数の顧客・案件で、Claude Code や Codex を同時に何本も動かす人。止まったことに気づけず放置した
経験がある人。手元から外へデータを出したくない人（受託・社内規程）。

**向かない**: エージェント 1 本で足りる人。チームで共有するダッシュボードが欲しい人（共有機能は無い）。
Windows の人。「仕事を分解して自動で回してほしい」人（そこは Cockpit などの方が進んでいる）。

## 5. この文書の限界（別モデルに反証させて残ったもの）

2026-09-20、この文書を別のモデル（`crosscheck.sh`）に「成立しないならどこが誤りか」と当てた。
出てきた指摘のうち、**直せたもの**と**直せず残っているもの**を分けて書く。

直したもの:
- 「認証エラー 1,012 **回**」と書いていたのは**エラー行の数**で、止まった出来事の数ではなかった。
  連続する同じエラーを 1 件にまとめて数え直し（989 件）、ついでに「止まってから人が戻るまで」を測って上の表に足した。

残っている限界（読む人はここを割り引いてください）:
- **「エージェントが増えると見失う」は、まだ因果として示せていない。** 示せているのは
  「19 本中 11 本が人待ちだった」という一時点の断面と、「止まった 989 件中 925 件はその会話に人が戻らなかった」という分布まで。
  本数別の見落とし率や放置時間の比較は測っていない。
- **「戻らなかった 925 件」は放置の上限値**。そこで用が済んだ・別の会話に移っただけ、も混ざる。区別できていない。
- **AIBoard を入れる前と後の比較をしていない。** 使っているのが 1 人なので、改善量の測定は無い。
- **試験 DT-01 が示すのは「表のとおりに動くこと」であって、表の判断が正しいことではない。**
  表そのものの妥当性は、上の実測（どの止まり方が多いか・人が戻らないか）から決めている。
- **`prove-local-only.sh` は 90 秒の標本**であって「常に外へ出さないこと」の証明ではない。README にもそう書いてある。
